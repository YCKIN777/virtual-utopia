# 虚拟乌托邦 BP3 需求规格说明书

> 文档版本：BP3-DRAFT-1.0
> 编制日期：2026-09-17
> 当前状态：需求规划阶段
> BP2基线：BP2-V1.1，永久冻结，不在BP3开发中修改

## 1. 背景与目标

### 1.1 背景

BP2已经完成以下基础能力：

- 五十户山林庄园城镇3D世界。
- 自由漫游、昼夜、雾气、风动和室内模式。
- Phase5持久化登录、world快照和刷新恢复。
- admin、editor、viewer角色权限。
- 拖拽式家园装扮编辑器。
- 多人在线Avatar、位置同步和idle/walk动画。
- 在线用户列表。
- 全局世界文字聊天。
- 完整交付包、验收文档和Obsidian只读归档。

BP3将在不改动BP2冻结基线的前提下，建设更完整的实时社交、家园安全和持续运营能力。

### 1.2 BP3业务目标

1. 提升用户实时互动能力，从文字聊天升级为实时语音沟通。
2. 强化私人空间控制，让家园具备明确的访客权限和门锁机制。
3. 建立可持续运营的世界事件与任务体系。
4. 引入资源收集和背包循环，形成探索、收集、使用和装扮的闭环。
5. 丰富Avatar表现和社区互动，提高用户留存与日常活跃。
6. 保持BP2的稳定性、性能和角色权限体系，不破坏现有业务。

### 1.3 BP3非目标

- 不修改BP2源码、交付包、冻结归档或Obsidian历史记录。
- 不重构BP2 3D场景美术基线。
- 不改变50户木屋点位、地形、生活广场、溪流和树木。
- 不引入复杂战斗、交易市场或开放经济系统。
- 不在BP3第一阶段实现跨服或大规模分布式实时通信。

## 3. P0需求

## 3.1 世界语音频道

### 3.1.1 功能目标

为登录用户提供多人实时语音对话能力，支持在世界漫游、生活广场和家园访问过程中自然沟通。

### 3.1.2 功能范围

1. 默认提供世界语音频道。
2. 支持加入、退出、静音、取消静音和关闭播放。
3. 显示当前频道在线成员及发言状态。
4. 支持管理员禁言或移出频道。
5. 支持编辑器和访客参与语音，但管理权限受角色约束。
6. 支持移动端麦克风权限申请和音频设备切换。
7. 支持网络中断后的自动重连。
8. 语音状态与Avatar在线状态关联。

### 3.1.3 技术建议

- 浏览器使用WebRTC传输音频。
- 小规模测试可使用P2P Mesh。
- 正式环境建议接入SFU方案，例如LiveKit、mediasoup或等效服务。
- BP3使用独立实时通信模块，不修改BP2 Phase6源码。
- 信令服务与媒体服务独立部署。

### 3.1.4 权限与安全

- 未登录用户不得进入语音频道。
- viewer可以参与世界语音，但不能管理频道。
- editor和admin按角色获得相应管理能力。
- 需要支持用户级静音、举报和服务端黑名单。
- 不默认录音，不在没有明确授权时保存语音。

### 3.1.5 预留接口

```text
GET    /api/bp3/voice/channels
POST   /api/bp3/voice/channels/:channelId/join
POST   /api/bp3/voice/channels/:channelId/leave
GET    /api/bp3/voice/channels/:channelId/participants
POST   /api/bp3/voice/token
POST   /api/bp3/voice/channels/:channelId/mute
POST   /api/bp3/voice/channels/:channelId/moderate
WS     /ws/bp3/voice/signaling
```

状态事件：

```json
{
  "type": "voice.participant.updated",
  "channelId": "world-main",
  "userId": 2,
  "speaking": true,
  "muted": false,
  "joinedAt": "2026-09-17T12:00:00.000Z"
}
```

### 3.1.6 验收标准

- 两个以上账号可进入同一语音频道并实时通话。
- 静音、退出、重连和发言状态显示正常。
- viewer无法执行管理员静音或踢出操作。
- 语音功能不影响BP2漫游、Avatar和文字聊天。

## 3.2 家园访客权限与门锁

### 3.2.1 功能目标

让家园主人可以精确控制访客能否进入院落和室内，并对访问行为进行授权和追踪。

### 3.2.2 家园访问状态

建议支持以下状态：

| 状态      | 说明                         |
| --------- | ---------------------------- |
| public    | 所有登录用户可参观公共区域   |
| private   | 仅主人可进入                 |
| request   | 访客需要申请，主人同意后进入 |
| whitelist | 仅白名单用户可进入           |

### 3.2.3 功能范围

1. 家园主人设置访问状态。
2. 家园主人维护访客白名单和黑名单。
3. 访客发起进入申请。
4. 主人同意、拒绝或设置临时授权。
5. 临时门锁码或邀请链接。
6. 访问记录记录进入时间、离开时间和访问者。
7. 私密家园只能从道路观看建筑外观。
8. 黑名单用户无法申请或重新进入。

### 3.2.4 预留接口

```text
GET    /api/bp3/homes/:plotId/access
PUT    /api/bp3/homes/:plotId/access
GET    /api/bp3/homes/:plotId/visitors
POST   /api/bp3/homes/:plotId/visitors
DELETE /api/bp3/homes/:plotId/visitors/:userId
POST   /api/bp3/homes/:plotId/access-requests
POST   /api/bp3/homes/:plotId/access-requests/:requestId/approve
POST   /api/bp3/homes/:plotId/access-requests/:requestId/reject
POST   /api/bp3/homes/:plotId/unlock
```

### 3.2.5 建议数据表

BP3新建独立表，不修改BP2 Phase5原有表：

- `bp3_home_access_rules`
- `bp3_home_visitors`
- `bp3_home_access_requests`
- `bp3_home_access_grants`
- `bp3_home_visit_logs`

### 3.2.6 验收标准

- private家园无法被普通访客进入。
- request模式可完成申请与审批。
- 白名单用户可直接进入。
- 主人可随时撤销访客权限。
- 非本人无法修改访问规则。

## 4. P1需求

## 4.1 世界事件与任务系统

### 4.1.1 功能目标

通过限时事件、长期任务和个人进度，形成可持续运营的世界内容。

### 4.1.2 功能范围

1. 世界事件定义和排期。
2. 个人任务、每日任务和协作任务。
3. 任务接取、进度、提交、完成和过期。
4. 奖励世界碎片、素材、称号或背包道具。
5. 生活广场、公共建筑和家园可绑定任务入口。
6. 管理员配置事件，editor可查看运营数据。
7. 任务状态实时同步到所有在线客户端。

### 4.1.3 预留接口

```text
GET    /api/bp3/events
GET    /api/bp3/events/:eventId
POST   /api/bp3/events
PUT    /api/bp3/events/:eventId
POST   /api/bp3/events/:eventId/activate
GET    /api/bp3/tasks
GET    /api/bp3/tasks/:taskId
POST   /api/bp3/tasks/:taskId/accept
POST   /api/bp3/tasks/:taskId/progress
POST   /api/bp3/tasks/:taskId/claim
```

### 4.1.4 建议数据表

- `bp3_tasks`
- `bp3_user_tasks`
- `bp3_task_progress`

## 4.2 素材资源收集与背包

### 4.2.1 功能目标

建立资源获取、存储和消耗闭环，为任务、装扮和世界事件提供基础经济系统。

### 4.2.2 资源类型

- 木材
- 石材
- 植物
- 布料
- 灯具零件
- 景观装饰材料
- 世界事件代币

### 4.2.3 功能范围

1. 世界探索采集。
2. 任务奖励掉落。
3. 背包查看、分类、堆叠和排序。
4. 素材解锁和家园装饰消耗。
5. 背包容量和扩展机制。
6. 管理员可调整掉落配置。
7. 背包变更持久化。

### 4.2.4 预留接口

```text
GET    /api/bp3/inventory

POST   /api/bp3/inventory/items
PUT    /api/bp3/inventory/items/:itemId
POST   /api/bp3/inventory/collect
POST   /api/bp3/inventory/consume
GET    /api/bp3/resource-catalog
```

### 4.2.5 建议数据表

- `bp3_resource_catalog`
- `bp3_inventories`
- `bp3_inventory_items`
- `bp3_inventory_transactions`
- `bp3_resource_nodes`

| 角色   | BP3能力                                                    |
| ------ | ---------------------------------------------------------- |
| admin  | 世界配置、事件管理、语音治理、用户和家园安全策略           |

## 7. 核心用户故事

### 7.1 世界语音

作为editor，我希望进入世界后加入语音频道，与其他居民实时交流。

验收：

- 可加入和退出语音。
- 可静音自己。
- 能看见正在发言的成员。
- 网络断开后能自动恢复。

### 7.2 家园门锁

作为家园主人，我希望设置私密家园和访客白名单，只允许指定用户进入。

验收：

- 非白名单用户无法进入。
- 访客可以发送申请。
- 主人可审批和撤销权限。

### 7.3 世界任务

作为居民，我希望参与世界事件并完成任务，获得碎片和装饰奖励。

验收：

- 任务入口可从场景或广场进入。
- 进度实时更新。
- 奖励进入背包或world快照。

### 7.4 资源背包

作为居民，我希望收集木材、石材和植物，用于制作或解锁家园素材。

验收：

- 采集后背包数量更新。
- 刷新后资源不丢失。
- 素材消耗后解锁对应装饰。

### 7.5 Avatar互动

作为居民，我希望使用表情和动作向其他用户表达情绪。

验收：

- 动作本人和其他用户可见。
- 动作不会影响移动和语音。

### 7.6 访客留言

作为访客，我希望在开放家园留下文字留言。

验收：

- 留言显示作者和时间。
- 主人可删除或置顶。
- 私密留言受权限控制。

## 8. 风险评估

| 风险                   | 影响           | 等级 | 缓解措施                           |
| ---------------------- | -------------- | ---- | ---------------------------------- |
| 语音带宽和并发过高     | 卡顿、掉线     | 高   | 使用SFU、码率控制、设备自适应      |
| 回声和噪声             | 沟通质量差     | 高   | 回声消除、噪声抑制、自动增益       |
| 语音隐私和骚扰         | 用户风险       | 高   | 静音、举报、黑名单、管理员治理     |
| 家园权限绕过           | 私人空间泄露   | 高   | 服务端权限校验，不信任前端         |
| 临时授权泄露           | 非法访问       | 中   | 短时令牌、单次使用、可撤销         |
| 任务和背包数据不一致   | 奖励丢失或重复 | 高   | 事务、幂等键、操作日志             |
| 实时事件风暴           | 服务过载       | 中   | 批量同步、限流、事件合并           |
| 移动端性能下降         | 用户流失       | 中   | 按需加载、媒体流优化、低功耗模式   |
| BP2兼容性回退          | 现有功能损坏   | 高   | BP3独立模块和独立表，禁止修改BP2   |
| 生产密钥和域名配置错误 | 无法上线       | 中   | 环境校验、部署清单、自动化冒烟测试 |

## 9. 非功能需求

### 9.1 性能

- 语音首连时间目标小于3秒。
- 世界同步在网络正常时延迟不超过300ms。
- 背包和任务操作响应小于500ms。
- 移动端保持稳定帧率，不引入重型3D资源。

### 9.2 可用性

- 单服务故障不得影响BP2只读归档。
- 语音服务不可用时，漫游和文字聊天仍可用。
- 关键操作需要重试和幂等保护。

### 9.3 安全

- 所有权限在服务端校验。
- 不信任客户端提交的用户ID、地块ID和角色。
- 敏感令牌不写入日志。
- 语音不默认存储。

### 9.4 可维护性

- BP3模块独立于BP2。
- 数据库迁移必须版本化。
- API必须有结构和错误码文档。
- 每个功能必须有E2E测试。

- P2访客留言板。
- 性能优化、正式部署和运维完善。

## 12. BP2兼容性约束

1. BP3不得修改BP2源码和冻结交付包。
2. BP3不得覆盖Obsidian中的BP2只读归档。
3. BP3使用独立目录、独立服务、独立数据表和独立路由前缀。
4. BP3新增功能通过适配层调用，不直接侵入BP2业务模块。
5. BP3发布前必须执行BP2完整回归，确认V1.1基线不退化。

## 13. 待确认事项

1. 语音正式方案选择LiveKit、mediasoup或自建SFU。
2. 世界语音是单频道还是生活广场/组团多频道。
3. 是否允许文字聊天和语音频道互相绑定。
4. BP3是否继续使用SQLite，还是升级到PostgreSQL。
5. 背包资源是否允许交易或仅用于个人消耗。
6. 家园临时门锁的有效期和撤销策略。
