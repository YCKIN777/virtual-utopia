## 3. 分阶段整改路线图

### 阶段一：P0 致命风险（立即，先于任何新功能）

1. **R-01 密钥治理**：轮换泄露密钥 → 明文改占位 → 加 `.gitignore` → 密钥扫描清零。
2. **R-05 数据备份**：落地 `backup-data.mjs` → 定时任务 → 恢复演练。
3. **R-08 崩溃恢复**：优雅关闭 + `process.on` 守卫 + pm2/服务守护。

> 完成标准：数据不再因崩溃丢失；密钥不再明文；服务异常可自愈。

### 阶段二：P1 高风险（1–2 周内）

4. **R-11 Git 版本控制**（为后续一切打底，优先）。
5. **R-02 / R-03 安全加固**（登录限流 + helmet/安全头）。
6. **R-09 / R-10 可观测性与告警**（结构化日志 + 告警）。
7. **R-06 迁移版本管理**。
8. **R-12 Lint/Prettier** + **R-14 前端入口收敛** + **R-16 启动编排** + **R-17 部署自动化**。

### 阶段三：P2 中风险（排期优化）

9. **R-19 / R-20 性能**（3D 懒加载 + WS 通道）→ **R-22 / R-23 测试完善** → 其余 P2（R-04/07/13/15/18/21）。

## 5. 备注（需人工决策 / 无法自动修复的点）

1. **R-01 密钥轮换**：泄露密钥必须在 DeepSeek 控制台轮换，脚本只能清理文件、无法轮换云端密钥（自动）。
2. **R-08 进程守卫**：需改动各 `server.js` 源码（属冻结范围内的服务入口），须人工确认「服务入口文件是否可改」，脚本只提供模板不直接改。
3. **R-11 Git 初始化**：`git init` 会改变仓库形态与首次提交策略，需人工确认提交范围、作者信息、是否保留 zip 快照。
4. **R-14 前端入口收敛**：三套入口的取舍依赖产品决策（哪套是主入口、哪套 legacy），无法自动判定。
5. **R-17 / R-21 容器化**：Docker 镜像与依赖版本需运维拍板，脚本只生成骨架。
6. **R-02 限流阈值 / R-03 CSP 白名单 / R-10 告警渠道**：参数依赖业务与运维口径，需人工定值。
7. **R-07 GBK 转码**：转码会改动历史文档字节，需人工确认「哪些 .txt 是废弃重复件」后再删除，避免误删唯一稿。
8. **冻结规则**：所有触及 `backend/src/{agents,routes,services,rag,phase4}` 及 `stage2~4_memory.md` 的改动，一律不得由脚本自动执行，必须逐项人工确认。
