## 2. 项目总体概述

### 2.1 Phase1：工程、UI与场景外壳

阶段目标：

- 建立前端、后端和本地工程基础。
- 完成全局HIG组件、等轴测矢量地图和六场景容器。
- 支持桌面端和移动端响应式展示。

交付成果：

- Vue 3、Vite、Vue Router、TailwindCSS前端。
- Express后端和基础健康接口。
- 按钮、卡片、弹窗、输入框、滚动容器和Toast等HIG组件。
- Canvas等轴测网格和SVG六点位建筑地图。
- 大院、议事亭、资源墙、书屋、小屋、远林六场景路由。
- PostgreSQL空表Schema占位，但不作为当前运行数据库。

### 2.2 Phase2：Agent与会话

阶段目标：

- 建立五个分支Agent和场景映射。
- 实现前端场景切换、消息收发和会话隔离。
- 保持公共会话与私聊会话边界。

交付成果：

- 阿禾-大院、知予-资源墙、叙白-议事亭、岁安-书屋、风禾-小屋。
- 远林不绑定Agent，前端禁止提交。
- 公共会话按场景隔离。
- 小屋私聊使用`prv_`会话，仅风禾可访问。
- 内存会话TTL、容量清理、越权和非法会话错误处理。
- 真实DeepSeek场景E2E，五个可用场景验证通过。

### 2.3 Phase3：RAG知识库

阶段目标：

- 新增独立RAG服务。
- 实现文档加载、分块、向量入库和相似度召回。

交付成果：

- `backend/src/rag/`独立RAG服务，监听`3100`。
- ChromaDB Node SDK和默认集合`virtual_utopia_rag`。
- `.md`、`.txt`文档加载和UTF-8读取。
- 默认800字符分块、120字符重叠和确定性chunkID。
- ChromaDB向量入库与余弦距离召回。
- 返回`chunk`、`source`、`chunkIndex`、`distance`、`similarity`。

### 2.4 Phase4：RAG与主Agent集成

阶段目标：

- 通过开关控制RAG检索增强。
- 将有效召回片段注入DeepSeek System Prompt。

交付成果：

- `backend/src/phase4/`独立集成模块。
- `ENABLE_RAG_ENHANCE`总开关，默认关闭。
- 相似度阈值和TopK配置。
- 开启时调用RAG并注入参考资料。
- 关闭时保持原Agent模型调用路径。
- 不修改原场景映射、会话隔离和Agent人设。

### 2.5 Phase5：SQLite持久化服务

阶段目标：

- 新增独立SQLite持久化元数据服务。
- 提供用户、会话、文档元数据和RAG日志持久化。
- 支持内存与SQLite双存储模式。

交付成果：

- `backend/src/phase5/`独立HTTP服务，默认监听`3300`。
- Node.js内置`node:sqlite`，启用WAL、外键和超时配置。
- `users`、`chat_sessions`、`knowledge_documents`、`rag_logs`四张表。
- 用户登录、角色鉴权和用户管理。
- 会话CRUD和服务重启恢复。
- 文档元数据CRUD。
- RAG日志写入和查询。
- `SESSION_STORAGE_MODE=memory|sqlite`模式切换。
- 不修改Phase1至Phase4源码。

## 3. 系统架构说明

```text
浏览器 5173
    │
    ▼
Vue 3 / Vite 前端
    │
    │ POST /api/scene/route
    ▼
Phase4主服务 3200
    │
    ├─ SESSION_STORAGE_MODE=memory
    │    └─ 原内存会话
    │
    ├─ SESSION_STORAGE_MODE=sqlite
    │    └─ HTTP → Phase5持久服务 3300 → SQLite元数据
    │
    ├─ ENABLE_RAG_ENHANCE=false
    │    └─ 直接调用DeepSeek
    │
    └─ ENABLE_RAG_ENHANCE=true
         │
         │ POST /api/rag/query
         ▼
       RAG服务 3100
         │
         ▼
       ChromaDB 8000
         │
         └─ 返回文档片段和相似度
              │
              ▼
         阈值过滤后注入DeepSeek System Prompt
              │
              ▼
          DeepSeek接口
```

关键边界：

- ChromaDB保存向量和文档chunk。
- Phase5 SQLite只保存元数据、会话、用户和日志。
- Phase5不接管向量存储。
- `memory`模式完全不调用Phase5。
- `sqlite`模式通过HTTP使用Phase5持久化适配器。

## 5. 非功能验收项

### 5.1 代码规范

- 新增JavaScript文件均通过`node --check`。
- 保留阶段一至阶段四原有测试和接口。
- Phase5代码独立放在`backend/src/phase5`。
- 未修改已冻结源码和记忆文档。

### 5.2 文件编码

- 新增源码和文档使用UTF-8。
- 未写入UTF-8 BOM。
- 换行格式为LF。

### 5.3 可部署性

- 前端可通过Vite构建。
- 后端以Node.js源码运行。
- RAG、Phase5和Phase4服务均支持本地独立启动。
- Chroma、SQLite数据目录均在项目外或独立目录维护。

### 5.4 容错能力

- Phase2网络异常、加载态和错误Toast已覆盖。
- Phase5 SQLite模式遇到服务不可用时返回明确错误。
- Phase5 memory模式不依赖Phase5服务。
- RAG增强关闭时不会访问RAG服务。
- 错误响应使用结构化JSON。

### 5.5 安全基础

- Phase5用户密码使用`scrypt`哈希保存。
- 登录使用HMAC签名Bearer Token。
- 服务间调用使用`X-Phase5-Service-Token`。
- 角色权限限制会话、文档和日志访问。

## 8. 缺陷说明

当前版本未发现已知重大缺陷。

已知非阻断限制：

- Windows x64下`chromadb@3.5.0`自带CLI存在架构限制，需使用Windows绑定启动方式。
- Phase5依赖Node.js内置`node:sqlite`，建议Node.js`>=22.5`。
- Linux和macOS尚未执行完整项目验收。
- PostgreSQL Schema仍为阶段一空表占位，不属于Phase5当前运行数据库。
- Phase5前端登录、文档列表和对话历史界面尚未纳入本轮交付。

以上限制不影响阶段一至阶段五已完成能力的自测验收结论。
