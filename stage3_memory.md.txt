# 虚拟乌托邦项目｜阶段三记忆文档
> 用途：定义阶段三目标、范围、子任务、验收标准、红线边界、前置条件；阶段三开发、巡检、归档使用。
> 重要声明：本文件仅为规划文档，**未收到【启动阶段三】正式指令前，禁止执行任何阶段三代码开发**；阶段一、阶段二已验收代码逻辑禁止修改。
> 关联档案：stage2_memory.md（阶段二完整归档）

## 1. 阶段三全局概览
项目名称：虚拟乌托邦项目
阶段名称：阶段三 - RAG知识库与文档检索能力开发
阶段目标：新增文档上传、文档解析、向量入库、语义检索能力；让各个场景下的Agent可以基于上传文档的内容做回答。
> 边界说明：阶段三只做文档RAG能力，**不做数据库持久化会话存储、不做用户登录账号体系（账号体系放到阶段四）**。

### 前置启动条件（必须全部满足，才可下发启动指令）
1. 已完成阶段二全部验收归档，stage2_memory.md 已落地保存 ✅
2. DeepSeek 真实API凭据配置完成（解决阶段二遗留环境项） ⏳
3. 向量库环境/依赖包确认选型就绪 ⏳
4. 下发明确指令：【启动阶段三开发】 ⏳

### 阶段三全局红线（不可突破）
1. ❌ **严禁修改阶段一、阶段二已验收代码**：地图渲染、场景切换、内存会话管理、私聊会话隔离、Agent角色人设、E2E测试脚本，不改动原有逻辑。
2. ❌ 不引入会话持久化存储：会话信息依旧保持阶段二内存会话方案，不将会话写入数据库。
3. ❌ 不开发用户注册、登录、权限、账号体系（阶段四范围）。
4. ✅ 新增代码完全隔离：RAG模块独立目录、独立路由，和原有场景Agent调度代码解耦。
5. ✅ 原有所有阶段二测试（npm run check、npm run test:e2e）必须保持全部通过，新增开发不能破坏原有功能。
6. ✅ 所有新增功能必须配套单元测试，上线前增加RAG专项E2E测试用例。

## 2. 阶段三子任务拆解（按顺序执行，串行开发+逐项巡检验收）
> 每个子任务完成后，必须执行独立巡检，巡检通过，门禁解除，方可进入下一个子任务。

### 子任务1：RAG基础模块搭建 & 依赖选型
目标：选定向量库、文档解析依赖；创建独立RAG模块目录结构，封装基础工具函数（文件读取、文本分割、Embedding调用）。
交付物：
1. RAG独立代码目录，与原有业务代码解耦。
2. 文档加载器：支持PDF/TXT等基础文档读取。
3. 文本分段（Chunk）切割工具，支持分段大小、重叠度配置。
4. Embedding调用封装（调用DeepSeek Embedding接口）。
5. 单元测试：文本分割、文件读取测试用例。
巡检验收项：
- 依赖可正常安装，无版本冲突。
- 文件读取、文本分段逻辑符合预期。
- 不改动任何阶段一/阶段二代码。
- npm run check 全部原有测试通过。

### 子任务2：向量库封装、向量入库与语义检索接口开发
目标：封装向量库，实现文档切片向量入库；开发独立语义检索API接口，输入查询文本，返回TopN相关文档片段。
交付物：
1. 向量库CRUD封装（新增向量、相似度检索、删除文档向量）。
2. 后端接口：文档向量入库接口、语义检索接口。
3. 单元测试：向量写入、相似度检索、文档删除测试。
巡检验收项：
- 上传文档切片可正常生成Embedding并写入向量库。
- 检索接口可根据问题召回相关文档片段。
- 原有阶段二全部测试用例保持通过。

### 子任务3：RAG能力接入场景Agent总控调度层
目标：在总控Agent调度逻辑中增加可选RAG上下文注入；Agent收到用户消息时，可选择调用检索接口，把检索到的文档片段放进prompt，再调用大模型。
> 注意：**原有Agent人设、对话逻辑不变，仅增加可选的文档上下文，不强制开启RAG**。
交付物：
1. 总控调度增加RAG检索开关配置。
2. 检索结果作为额外上下文，注入给对应场景Agent。
3. 单元测试：Agent调用RAG、不调用RAG两种分支。
巡检验收项：
- 开启RAG：Agent回答会引用上传文档内容。
- 关闭RAG：保持阶段二原有对话逻辑不变，行为完全一致。
- 五个场景Agent人设不变，不破坏私聊会话隔离规则。

### 子任务4：前端文档上传页面 & 文档管理UI开发
目标：新增前端文档上传组件，支持上传文件、查看已上传文档列表、删除文档；RAG开关控制面板。
交付物：
1. 文档上传组件，文件选择+上传进度提示。
2. 文档列表，展示已上传文档名称。
3. 删除文档按钮（同步删除后端向量库对应向量）。
4. RAG启用开关（全局/按场景切换）。
巡检验收项：
- 前端上传文件可成功提交后端，完成解析入库。
- 删除文档，后端向量同步清除。
- UI不破坏原有地图、对话面板页面布局。

### 子任务5：阶段三全链路E2E测试 & 整体巡检验收（阶段三收尾任务）
目标：编写RAG专项E2E测试；全链路跑通：前端上传文档 → 解析入库 → 场景对话触发检索 → Agent引用文档回答；同时回归所有阶段二原有功能。
交付物：
1. RAG专项E2E测试脚本，加入 npm run test:e2e 套件。
2. 完整回归测试：验证阶段二所有功能（会话隔离、私聊越权、远林拦截等）不受新增RAG模块影响。
3. 阶段三整体巡检报告。
巡检验收项：
✅ RAG全链路流程正常
✅ 原有阶段二全部E2E测试通过
✅ 红线扫描：没有改动阶段一/二核心代码、没有新增会话持久化、没有账号登录代码
结论：阶段三整体验收完成，阶段三关闭。

## 3. 阶段三巡检通用模板（每个子任务巡检都使用）
```markdown
## 【阶段三巡检｜子任务X：xxx】
### 核心监控原则
子任务范围：xxx
✅ 允许：完成本子任务约定交付物、单元测试、日志完善。
❌ 红线禁止：
1. 修改阶段一、阶段二已验收代码逻辑。
2. 新增会话持久化数据库存储。
3. 新增用户登录、账号权限体系代码。
4. 破坏原有内存会话隔离、私聊权限控制逻辑。

### 分项巡检清单
1. 交付物检查：是否产出本子任务约定交付物。
2. 单元测试：新增单元测试全部通过。
3. 回归测试：npm run check，原有阶段二测试全部通过。
4. 代码红线扫描：无违规改动阶段一/二代码，无禁止新增功能。
5. 异常场景：处理文件损坏、超大文件、向量检索空结果等异常分支。

### 巡检输出模板
>【阶段三巡检｜子任务X：xxx】
>✅ 通过项：xxx
>⚠️ 待整改项：xxx（如有）
>🚫 违规项：xxx（如有）
>结论：继续执行 / 暂停并整改
### 放行规则
结论为【继续执行】，本子任务门禁解除，进入下一个子任务；出现违规项必须暂停开发，整改后重新巡检。
