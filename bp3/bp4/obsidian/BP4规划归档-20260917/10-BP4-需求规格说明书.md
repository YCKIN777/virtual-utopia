# 虚拟乌托邦 BP4 需求规格说明书

> 文档版本：BP4-SPEC-DRAFT-1.0  
> 编制日期：2026-09-17  
> 基线：BP1、BP2、BP3全部冻结

## 1. 背景

BP1完成了前端工程与六场景，BP2完成了Agent、RAG、持久化和3D家园，BP3完成了语音、家园权限、事件任务、背包、Avatar动作和留言板。

现有系统已经具备完整业务闭环，但主要面向本机和单机验收：

- SQLite适合单机，不适合多实例和跨节点事务。
- presence、聊天、事件和Avatar主要使用轮询。
- mediasoup仍为单机Worker，缺少TURN和集群调度。
- 缺少运营后台、监控告警、自动备份和正式CI/CD。

BP4的目标是完成生产化升级，不重写BP1~BP3业务。

## 2. BP4业务目标

1. 支持至少500名日活用户和100名同时在线用户。
2. 支持服务重启、节点故障和网络切换后的状态恢复。
3. 将关键数据从单机SQLite迁移到PostgreSQL。
4. 用统一实时通道替代关键业务短轮询。
5. 让语音在公网、移动网络和NAT环境可稳定连接。
6. 建立运营后台、监控、告警、备份和回滚能力。
7. 保持BP1~BP3已有用户数据、家园布局和公开接口兼容。

## 3. BP4非目标

- 不重新规划3D场景、山体、溪流、广场或50户木屋。
- 不改变BP3已有角色语义和权限边界。
- 不在BP4 P0引入AI NPC或自动生成世界。
- 不实现开放经济、交易市场或跨服务器资产流通。
- 不修改冻结的Obsidian归档和交付包。

## 5. P0需求

### 5.1 生产持久化

系统必须支持PostgreSQL，同时保留BP3 SQLite数据迁移路径。

要求：

- 使用版本化迁移工具。
- 用户、会话、world快照、语音、权限、任务、背包和留言数据可迁移。
- 迁移前后数量、校验和、归属关系一致。
- 支持蓝绿切换和回滚到冻结快照。

验收：

- 迁移100%可重复执行。
- 迁移后页面刷新、家园恢复、任务和背包读取一致。
- 回滚演练在30分钟内完成。

### 5.2 统一实时通道

新增统一WebSocket实时通道，替代presence、聊天、Avatar、事件和留言的核心轮询。

要求：

- 连接鉴权使用短时ticket。
- 支持订阅频道、消息序号、ACK和断线续传。
- 支持presence、聊天、Avatar、任务、背包和事件事件类型。
- 断线后5秒内恢复，保留最近事件。

验收：

- 单连接可订阅多个业务频道。
- 100个并发连接稳定运行。
- 重连后不重复提交库存和奖励。

### 5.3 语音集群

要求：

- 支持多个mediasoup Worker。
- 支持按语音房间分配Router或节点。
- 提供TURN服务。
- 配置公网`announcedAddress`、RTC端口范围和健康检查。
- 节点故障时新连接自动转移，已连接用户可重连。

验收：

- 公网和移动网络可加入语音。
- 单Worker故障不导致全站语音中断。
- 语音服务不可用时，漫游、聊天和任务继续工作。

### 5.4 安全基线

要求：

- 访问令牌轮换和撤销。
- 角色、地块、资源和服务端操作四维校验。
- 登录、申请、上传、聊天和库存接口限流。
- 奖励、库存和授权写入幂等。
- 安全审计日志可查询。

验收：

- 伪造用户、角色、地块和作者字段全部被拒绝。
- 重复请求不会重复发奖或超扣库存。
- 关键安全事件可追溯到用户、IP、时间和资源。

### 5.5 可观测性与运维

要求：

- 结构化日志。
- 指标：请求量、错误率、延迟、WebSocket连接数、语音节点状态、数据库连接。
- 健康检查和就绪检查。
- 告警规则和值班处理手册。
- 自动备份、恢复演练和回滚手册。

验收：

- 5分钟内定位一次接口错误高峰。
- 数据库备份可恢复到独立环境。
- 关键告警能送达管理员渠道。

## 6. P1需求

### 6.1 世界运营后台

- 事件、任务、资源、奖励的创建、编辑、预览和发布。
- 定时任务、结束时间和活动状态管理。
- 奖励发放审计和补发。

### 6.2 模板化内容

- 事件模板。
- 任务链模板。
- 资源节点模板。
- 奖励包模板。

### 6.3 移动端与PWA

- 移动端首屏和3D加载优化。
- 低功耗模式。
- 离线缓存静态资源。
- 麦克风权限和弱网提示。

### 6.4 数据看板

- 日活、在线人数、语音时长、任务完成率、资源采集量和家园活跃度。
- 管理端只读展示和导出。

## 7. P2需求

- AI NPC和动态对话任务。
- 实时语音识别、合成和翻译。
- 多世界、多区域和跨节点路由。
- UGC家园模板、素材包和订阅赛季。

## 8. 核心用户故事

### 8.1 居民

作为居民，我希望在弱网和移动网络下仍能进入世界、聊天、加入语音和完成任务。

验收：

- 断网后重连恢复。
- 任务和背包不重复或丢失。
- 语音可重新加入。

### 8.2 家园主人

作为家园主人，我希望权限设置在服务重启后仍生效，并可在新节点上恢复。

### 8.3 运营人员

作为运营人员，我希望通过后台创建活动、查看数据并处理异常奖励。

### 8.4 运维人员

作为运维人员，我希望快速知道哪个服务异常、为什么异常以及如何回滚。

## 9. 非功能需求

| 类型     | 目标                           |
| -------- | ------------------------------ |
| 可用性   | 月度可用性不低于99.9%          |
| 实时延迟 | WebSocket业务事件P95小于300ms  |
| 语音延迟 | 正常网络端到端P95小于300ms     |
| 并发     | 100在线用户、10并发语音房间    |
| 恢复     | 单节点故障30秒内完成新连接转移 |
| 安全     | 关键写入全部服务端鉴权         |
| 兼容     | BP3冻结数据和API契约保持可迁移 |
| 性能     | 移动端稳定30FPS，目标60FPS     |

## 10. 待确认事项

1. PostgreSQL、Redis和对象存储的部署位置。
2. mediasoup继续自建还是切换LiveKit等托管SFU。
3. 是否允许聊天和语音短期留存，以及保存周期。
4. 数据看板是否包含用户级行为明细。
5. 多环境是否为dev、staging、prod三套独立资源。
